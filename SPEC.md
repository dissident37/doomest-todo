# Самый тупой туду-лист — требования (MVP)

Nov 7, 2026 · @Konstantin

## Проблема и идея

Приложение заменяет бесцельное листание телефона одним взглядом на свои дела: открыл, увидел, выбрал одно и пошёл делать.

**Проблема.** Копятся долгие несрочные дела, которые висят месяцами и годами: купить люстру и стол в детскую, разобрать подвал и балкон. Плюс ежедневное: спорт, английский. Свободное время есть, но уходит на рилсы, потому что дел в этот момент нет перед глазами.

**Идея.** Иконка на телефоне, которую тыкаешь вместо соцсетей. Сразу открывается список дел, и выбираешь одно сам. Приложение ничего не планирует и не советует: его задача — напомнить, что дела есть.

**Для кого.** В первую очередь для себя. Публикация в Google Play возможна потом.

## Принципы

Главное требование — скорость. Приложение конкурирует с рилсами за одну секунду внимания.

**Это:**

- один плоский список, который листаешь и смотришь;
- список несрочных долгих дел и ежедневных привычек;
- сначала телефон.

**Это не:**

- не планировщик проектов: нет подзадач и этапов, этап просто дописываешь в заголовок или описание;
- нет дедлайнов, напоминаний, тегов;
- нет фильтров по времени, сложности или категориям.

**Нефункциональные требования:**

- открывается сразу со списком: без заставки, логина и спиннера;
- работает без интернета;
- новое дело добавляется за пару секунд.

## Функционал MVP

MVP — это два экрана (список и карточка дела) и два типа дел (обычное и ежедневное).

**Главный экран — список**

- Вертикальный список овальных карточек, как список чатов. На карточке только заголовок.
- Порядок задаёт пользователь, автосортировки нет.
- Кнопка «+» добавляет дело. Новое дело встаёт в конец списка.

**Карточка дела (по нажатию)**

- Заголовок — обязателен, редактируется в любой момент.
- Описание — свободный текст любой длины, можно оставить пустым.
- Переключатель «Ежедневное».
- Кнопка «Удалить насовсем» внизу, с подтверждением.
- Изменения сохраняются сами, без кнопки «Сохранить».

**Типы дел**

| Тип | После «сделано» (свайп) | Как убрать насовсем |
| --- | --- | --- |
| Обычное | Исчезает навсегда | Свайп или кнопка в карточке |
| Ежедневное | Исчезает до начала следующего дня, потом возвращается | Только кнопка «Удалить насовсем» в карточке |

Предложение по умолчанию: «следующий день» наступает в 00:00 по времени телефона, а дело возвращается на своё прежнее место в списке.

**Экспорт и импорт (бэкап)**

- Меню в шапке главного экрана: «Экспорт» и «Импорт».
- Экспорт сохраняет весь список в один JSON-файл через системное окно «Поделиться / Сохранить»: в файлы, Google Drive, почту, мессенджер.
- Импорт читает такой файл и после подтверждения заменяет текущий список. Без импорта экспорт бесполезен.
- В файле есть номер версии формата, чтобы новые версии приложения читали старые бэкапы.

## Жесты и взаимодействие

Жестов четыре, и у каждого один смысл во всём приложении.

| Жест | Действие |
| --- | --- |
| Свайп влево или вправо | «Сделано»: дело уходит с экрана |
| Нажатие | Открыть карточку дела |
| Удержание + перетаскивание | Поменять порядок |
| Кнопка «Отменить» на плашке после свайпа | Вернуть дело на место |

**Почему так**

- Стороны свайпа в крупных приложениях не стандартизированы: в Todoist и Asana вправо завершает, в iOS влево удаляет, Todoist вообще даёт настроить. У нас основное действие одно, поэтому обе стороны делают одно и то же.
- Nielsen Norman Group: свайп не виден, люди ждут от него «убрать», смысл должен быть одинаковым везде. Важные действия не прячут только в свайп, поэтому «Удалить насовсем» — видимая кнопка в карточке.
- Material Design: после свайпа — плашка внизу с названием дела и кнопкой «Отменить» на несколько секунд: случайный свайп сделать легко.
- Удержание + перетаскивание — общепринятый жест для порядка (Asana и др.), с горизонтальным свайпом не конфликтует.
- Горизонтальные свайпы не используются ни для чего другого (например, для перехода между экранами).

Источники: [NN/g — Contextual Swipe](https://www.nngroup.com/articles/contextual-swipe/) · [Todoist — swipe actions](https://www.todoist.com/help/articles/-D5DQOQz6) · [Asana Community](https://community.asana.com/t/any-plans-to-swipe-to-delay-due-dates-like-todoist-and-others/56) · [Flutter — swipe to dismiss](https://docs.flutter.dev/cookbook/gestures/dismissible)

## Голосовой ввод

В MVP голос работает через системную клавиатуру, свой микрофон не пишем.

- Поведение стандартное: текст вставляется туда, где стоит курсор; выделенный текст заменяется; в пустое поле пишется заново.
- Именно так работает голосовой ввод клавиатуры (Gboard и др.) в любом текстовом поле, так что он есть в заголовке и описании сразу.
- Требование к приложению: обычные текстовые поля, которые не мешают клавиатуре диктовать.

Своя кнопка микрофона нужна, только чтобы создавать дело голосом одним тапом с главного экрана. Это вторая версия.

## Данные и хранение

Все данные хранятся только на телефоне, сервера и аккаунта нет. Модель данных сразу готова к синхронизации, чтобы потом не переделывать.

**Сущность «Дело»**

| Поле | Тип | Зачем |
| --- | --- | --- |
| id | UUID | Уникален на любом устройстве, без конфликтов при синхронизации |
| title | строка, обязательно | Заголовок |
| description | текст, можно пусто | Описание |
| is\_recurring | да/нет | Ежедневное дело |
| position | число или строка для сортировки | Порядок в списке |
| hidden\_until | дата, можно пусто | До какого дня скрыто ежедневное дело |
| deleted | да/нет | Мягкое удаление: нужно для отмены и будущей синхронизации |
| created\_at / updated\_at | дата-время | История и разрешение конфликтов при синхронизации |

«Сделано» для обычного дела ставит deleted, для ежедневного — hidden\_until на завтра. Бэкап — ручной экспорт в JSON-файл и импорт обратно (см. «Экспорт и импорт»). JSON повторяет поля этой таблицы.

## Стек и архитектура

**Стек: React Native + Expo, TypeScript.** Решено 9 ноября 2026.

**Критерии выбора**

1. Скорость запуска с иконки.
2. Плавные свайпы и перетаскивание.
3. Надёжное локальное хранение: данные не должны пропадать.
4. Путь к синхронизации и Google Play без переписывания.
5. Работа с Claude Code и ценность для портфолио.

**Почему Expo**

- Разработка идёт на слабом Windows-ноутбуке без Mac (8 ГБ RAM). Код запускается на телефоне через Expo Go, локальная сборка Android и Android Studio не нужны. APK собирается в облаке EAS Build: бесплатно до 15 сборок Android в месяц (ноябрь 2026).
- Есть путь на iPhone без Mac: EAS собирает iOS в облаке. Для установки на iPhone нужен платный аккаунт Apple Developer.
- Есть путь на ПК: Expo web.
- Жесты на react-native-gesture-handler и Reanimated — почти нативное ощущение.
- TypeScript удобен для работы с Claude Code, React Native востребован в портфолио.

**Что отпало**

| Вариант | Почему нет |
| --- | --- |
| Kotlin + Jetpack Compose | Лучшее качество на Android, но тяжёлая локальная сборка на этом ноутбуке, iOS — только через Mac |
| PWA | Жесты слабее; главный плюс — iPhone без Mac — в MVP не нужен |
| Flutter | Тяжёлая локальная сборка, iOS — только через Mac |
| .NET MAUI | Нет веба, iOS — только через Mac |

**Архитектура: local-first.** Локальная база SQLite на телефоне — источник правды: приложение открывается из неё сразу и работает без сети. Синхронизация потом добавляется отдельным слоем поверх (сервер с API и БД), модель данных к этому уже готова.

**Что учесть на Android**

- targetSdk 36 — обязателен для Google Play с 31 августа 2026.
- Edge-to-edge обязателен: кнопка «+», плашка «Отменить» и шапка учитывают системные отступы и клавиатуру.
- Жест «Назад» от края экрана может конфликтовать со свайпом карточки — проверять на телефоне.
- Крупный системный шрифт (до 200%). Предложение: у карточки минимальная высота вместо фиксированной.
- «Новый день» пересчитывать при каждом возврате в приложение: полночь в фоне, смена часового пояса, перевод часов.
